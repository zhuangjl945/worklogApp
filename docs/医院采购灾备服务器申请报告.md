## 一、申请事由

我院核心业务系统（HIS、电子病历EMR、LIS、PACS、手麻、重症、医保结算、互联网医院等）已全部依赖数据库和虚拟化平台运行，业务连续性和数据安全性直接关系医疗质量与患者安全。经信息科自查并结合2025年度等级保护测评结论，我院目前**尚未建成独立、可验证、防篡改的灾备（备份）体系**，存在"备份与生产同源、无离线副本、无异地副本、恢复无演练、备份容量即将耗尽"五类突出问题，一旦发生硬件故障、误删除或勒索病毒加密事件，将面临业务长时间停摆和诊疗数据永久丢失的重大风险。

为此，信息科申请采购灾备（备份）服务器（备份一体机）1套及配套备份存储、专用万兆网络、企业级备份管理软件与5年原厂服务，预算总额人民币【 】万元（大写：【 】）。现将有关情况报告如下，请审议批准。

### （二）现存主要问题

1. **备份与生产同机房、同网段、同权限域，不满足"3-2-1"要求。** 现有备份目的地为院内NAS，与生产环境同处核心机房，主机房发生火灾、水患、供电事故或勒索病毒横向扩散时，生产数据与备份数据会被同时摧毁。近年国内医院被勒索攻击案例中，约七成存在"备份文件一并被加密"的情况，恢复只能依赖支付赎金或重建。
2. **无异地灾备副本，等保测评已判定为不符合项。** GB/T 22239-2019 三级要求"应提供数据的异地备份和恢复机制"，2025年度测评报告中该项为**部分符合/不符合**（见附图4），是上级卫生健康行政部门网络安全执法检查的必查点，也是三级医院评审、电子病历应用水平分级的现场核查项。
3. **备份成功率不可信、恢复无演练、无证据链。** 现靠人工脚本+每周人工核查日志，2025年累计备份失败/未执行【23】次；全年仅完成【1】次恢复演练，且未覆盖数据库全量恢复；备份可恢复性、恢复时长均无法举证，事故追责时信息科将承担主要管理责任。
4. **RPO/RTO 无保障。** 归档日志仅保留【3】天，最坏情况可丢失【3】天数据（RPO=3天）；手工恢复一台数据库虚拟机实测耗时【6~10】小时（RTO远超可接受范围）。按行业标准，核心交易系统应做到 RPO≤15分钟、RTO≤2小时。
5. **备份容量即将耗尽，增长无解。** 现有备份存储【48】TB，剩余可用【5.6】TB，按数据年增【25】%、保留期需延长至"病历15年、住院病历30年"的要求测算，预计【3】个月内无法再容纳新的全备副本，被迫缩短保留周期，风险持续放大。
6. **老设备已过保、无原厂服务。** 现有备份服务器【2018】年购置，已过保【2】年，主板与硬盘备件停产，故障后平均修复时间无法承诺，形成二次故障风险。
7. **备份占用生产网络与存储IO，影响业务性能。** 备份窗口与夜间批量结算、数据上传（医保、全民健康信息平台）重叠，多次引发收费卡顿投诉。

### （二）业务连续性与患者安全的现实需要

我院日均门急诊【 】人次、日均出院结算【 】笔、在院患者【 】人。按历史故障测算，HIS/EMR 不可用每30分钟即造成：门诊排队积压约【300】人次、收费与医保结算被迫转手工、急诊与手术核查效率下降、患者投诉与舆情风险显著上升。同时， PACS/影像与病历属于法定保存年限数据（门急诊病历≥15年、住院病历≥30年），一旦丢失不可补正，涉及医疗纠纷举证责任，法律后果远重于设备投入。

### （三）勒索病毒防护的紧迫需要

医疗行业是勒索病毒攻击的重点目标，攻击路径多为远程运维入口、弱口令、邮件钓鱼与备份账户被撞库。本项目要求具备**不可变备份（WORM/对象锁）、离线Air-Gap副本、独立管理域与多因素认证、备份异常行为检测告警**，是当前唯一被验证有效的"最后一道防线"。仅靠防火墙和杀毒软件无法防止备份被删改。

### （四）不采购的后果分析

1. 等保测评与卫生执法检查的不符合项无法闭环，可能被通报、约谈，影响医院评审与等级创建；
2. 数据量与法规保留年限倒逼下，被迫压缩保留周期，出现"出事时无可用副本"的极端后果；
3. 老设备故障概率上升，若同时发生生产与备份故障，将造成不可逆损失；
4. 一旦停摆，直接经济损失与声誉损失远高于本项目预算（详见第十部分测算）。

## 四、建设目标

总体目标：用1个建设周期，建成"**本地集中备份 + 防篡改副本 + 院内异地/离线副本 + 可验证恢复演练**"的一体化灾备体系，实现核心系统"备得全、备得快、恢得了、证明白"。

| 指标项 | 现状 | 建设目标 | 验收口径 |
|---|---|---|---|
| 备份覆盖率 | 约【62】% | 100%（核心系统+虚拟化+文件+影像索引） | 备份策略清单与作业成功率报表 |
| 核心系统 RPO | 最长3天 | ≤15分钟（数据库日志级/CDP） | 事务日志连续性校验 |
| 核心系统 RTO | 6~10小时 | ≤2小时（单VM可≤15分钟挂载恢复） | 恢复演练计时报告 |
| 副本份数与位置 | 1份、同故障域 | ≥3份、2种介质、1份离线或异地（3-2-1） | 副本拓扑与Air-Gap验证 |
| 备份数据保留 | 7天 | 日备保留28天、月备12个月、年备3年（法规年限数据按制度延长） | 保留策略与恢复点列表 |
| 防篡改能力 | 无 | 不可变备份（WORM/对象锁）+离线副本+独立管理域 | 篡改尝试被阻断的测试记录 |
| 恢复可验证性 | 人工、无记录 | 自动化沙箱恢复验证，每月自动出报告 | 验证报告≥12份/年（含首年） |
| 备份网络 | 占用生产网 | 独立万兆备份网，业务零影响 | 网络拓扑与流量隔离测试 |
| 演练机制 | 1次/年、临时 | ≥2次/年、脚本化、有影像与签字记录 | 演练方案+总结报告 |
| 运维自动化 | 人工脚本 | 统一控制台、告警对接运维平台、失败自动重试 | 控制台截图与告警联调记录 |

## 六、容量与性能测算依据

**1. 备份窗口测算（能否一夜备完）**

需备份有效数据约【125】TB，允许备份窗口为 22:00—06:00（8小时），扣除首周以外的增量比例约 3%/日：

- 首次全备：125TB ÷（15TB/小时 × 8小时）≈ 需【11】个夜间分批完成（可接受，一次性）；
- 每日增量：约 3.75TB ÷ 15TB/小时 ≈ 0.3 小时，裕量充足；
- 结论：需配置 ≥4×10GE 备份专网与并发能力≥100 作业，方可满足窗口要求。

**2. 存储容量测算（3~5年规划）**

| 项目 | 取值 | 说明 |
|---|---|---|
| 起始需保护容量 | 【125】TB | 台账汇总，不含磁带归档 |
| 年增长率 | 【25】% | 近三年实测均值，影像增长为主 |
| 保留策略 | 日28天+月12个+年3个 | 约【43】个恢复点，永久增量+合成全备 |
| 副本份数 | 主副本1份 + 异地/离线副本1份 | 离线副本按精简副本系数0.35计 |
| 重删压缩比 | 综合【10】:1 | 结构化25:1、虚拟化10:1、影像/JPG仅1.5:1 |
| 第1年所需可用容量 | 约【95】TB | 125×1.25÷10×(1+0.35)+RAID与缓存裕量 |
| 第3年所需可用容量 | 约【150】TB | 年增25%累计 |
| 第5年所需可用容量 | 约【235】TB | 通过不停机扩容满足 |

**结论：本期按"3年不扩容、5年可扩展"配置，有效容量不低于【150】TB（重删压缩后），物理裸容量不低于【220】TB（RAID6/TP 之后口径），并预留硬盘槽位≥【8】个。**

**3. 机房条件测算**

满载功耗约【1.2】kW/台×【2】+ 网络约0.3kW，合计新增约【2.7】kW，需 UPS 余量、空调制冷量与【1】个标准机柜位。经与总务科初步确认，现有【核心机房/第二机房】具备扩容条件（如不具备，需同步列入配电与制冷改造）。

## 十、效益分析

### （一）风险规避与经济效益测算

| 情景 | 发生概率（年） | 单次损失测算 | 年期望损失 |
|---|---|---|---|
| HIS/EMR 停摆4小时（硬件故障，无有效副本） | 【8】% | 门诊停诊与退号、手工单据、加班与投诉处置约【12】万元 | 【约1.0】万元 |
| 勒索病毒加密且备份同时被毁（需重建） | 【3】% | 停业恢复、数据重建、监管处罚、舆情与诉讼约【300】万元起 | 【约9.0】万元 |
| 病历/影像数据永久丢失 | 不可估 | 医疗纠纷举证不能、评审不通过、法律责任 | 不可估（本项目为唯一兜底手段） |
| 等保/执法检查看板问题被通报 | 现状已存在 | 整改、复测费用与信用影响约【5】万元 | 【约5.0】万元 |

一次灾备体系建成的直接投入约为上述年期望损失的【 】倍，且可从根本上消除"数据永久丢失"这一不可承受风险。此外建成后预计每年可节约人工备份运维工时约【240】人时，减少夜间人工值守与故障排查投入。

### （二）管理与社会效益

1. 备份与恢复从"经验驱动"转为"制度+证据驱动"，形成可审计的闭环，减轻信息科及分管领导的履职风险；
2. 满足等级保护、卫生执法检查、三级医院评审、电子病历分级评价等多项检查要求，避免整改通报；
3. 缩短故障恢复时间，直接减少门诊停摆与患者等待，提升患者满意度和医院声誉；
4. 为后续"双活/同城灾备""信创迁移""数据要素治理与科研数据中心"奠定基础，避免重复投资。
